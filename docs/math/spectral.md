# Spectral/RMT descriptor: an input control, not another embedding

Implemented in `spectral.py`, driven by `spectral_sweep_raw.py`/`spectral_walkthrough.ipynb`. This is a third descriptor branch alongside Graph2Vec and eigenvector centrality, but it varies a different axis of the comparison. Eigenvector centrality asks "holding the filtered graph fixed, does a cheaper *descriptor* do as well as Graph2Vec's learned one?" This branch asks the complementary question: "holding the descriptor style fixed (both handcrafted, both eigen-derived), does the *input* matter?" — it operates on the raw windowed correlation matrix directly, with no distance transform, no thresholding, and no graph construction at all. Its per-window feature table is also a first-class, independently pickled output (`outputs/{index_code}_spectral_features_{epoch_length}d.pkl`), not just an intermediate on the way to clustering.

## No graph: eigendecomposition of the correlation matrix itself

`window_spectral(C, stock_names, epoch_length)` takes the raw correlation matrix `C` straight from `load_arm(...)["correlation_matrices"]` (the same per-window matrices `networks.build_arm_networks` already computes and pickles — no recomputation, no re-download) and runs `np.linalg.eigh(C)`, sorted descending. Everything downstream is derived from that one eigendecomposition; there is no `threshold_graph`/`mst_graph`/`tmfg_graph` step, so `spectral_sweep_raw.py` only has a raw-arm sweep (see "Currently raw-only" below — the embedding-geometry branch, `embedding_geometry_sweep.py`, uses Graph2Vec only, not spectral; see [`embedding-geometry.md`](embedding-geometry.md)).

## The current 9-feature set

`SPECTRAL_FEATURE_COLUMNS` (fed to `fit_spectral_embed`/`transform_spectral_embed`) was reduced from 14 columns to 8 in a redundancy audit — every feature below except `pr_corr_v1` is what survived that audit, and *why* it survived is part of its definition here, not a separate history to consult elsewhere. The audit's method: correlation/PCA-loading analysis and regime-conditional effect sizes on real data, not just theory. Headline finding: the removed features left **zero** feature pairs with |Pearson r| > 0.90 in the retained 8-feature set, down from 6–8 (out of 91 possible pairs) in the old 14-feature set, while the aggregate ability to separate a calm window from a crisis window in the fitted PCA space was unchanged to within noise (10.31× vs. 10.38× the typical window-to-window step, SP500/132d). `pr_corr_v1` — the leading eigenvector's participation ratio — was one of the features that audit removed (see "Eigenvector geometry" below) and has since been reinstated by explicit request, ahead of `pr_corr_v2` in column order; the audit's original redundancy finding for it is kept below, not erased, since it directly bears on how to read the feature once it is back in the fitted PCA space.

| Feature | Definition | What it measures | Why retained |
|---|---|---|---|
| `mu` | `networks.mu_offdiag(C)` — mean off-diagonal correlation | Market-mode level | Near-perfectly collinear with the old `lambda_1`/`lambda_1_share` (r ≈ 0.997–1.000 — RMT theory predicts $\lambda_1 \approx N\mu$ when one mode dominates) and with the old `spectral_gap` (r ≈ 0.978–0.989); `mu` is the sole survivor of that four-way near-duplicate cluster, kept because it's the same quantity `fit_regime_order` already ranks clusters by pipeline-wide (see [`regime-detection.md`](regime-detection.md)) |
| `sigma_offdiag` | `networks.sigma_offdiag(C)` — std of the same off-diagonal entries `mu` averages | Dispersion/heterogeneity of pairwise correlations — are all pairs moving together uniformly, or is it a few clustered sectors dragging up the mean? | Added by the audit: cheap (same `np.triu_indices_from` extraction as `mu`), and a property `mu`'s mean alone can't distinguish. Moderately correlated with `lambda_2_share` (r≈0.84) but the least `mu`-correlated of the "structure" features |
| `lambda_2_share` | $\lambda_2 / N$ | 2nd factor strength, N-normalised | Genuinely different information from `mu` (weak-to-moderate correlation, sometimes even positive) |
| `lambda_3_share` | $\lambda_3 / N$ | 3rd factor strength, N-normalised | Same reasoning as `lambda_2_share` |
| `lambda_4_share` | $\lambda_4 / N$ | 4th factor strength, N-normalised | Same reasoning; `lambda_5` (dropped) was redundant with both this and `n_above_mp` |
| `n_above_mp` | `int((lambdas > mp_edge).sum())` | Count of eigenvalues clearing the Marchenko–Pastur bulk edge — breadth of active factors | *Negatively* correlated with `mu`/`lambda_1`-family features (r=-0.43 to -0.75): as the market mode strengthens, the spectrum collapses onto one dominant factor and fewer eigenvalues clear the noise floor. Magnitude of the dominant mode and breadth of active factors are different axes that happen to move in opposite directions — worth keeping both |
| `spectral_entropy_bulk` | See "Singularity" below | Evenness/shape of the sub-`mp_edge` noise bulk | The single best-performing feature in the audit: lowest redundancy with the `mu` cluster (r=-0.13 to -0.66) and the largest or near-largest crisis-conditional effect size in most real combos (up to Cohen's d = -1.78) |
| `pr_corr_v1` | `participation_ratio(V[:, 0])` — see below | Localisation/delocalisation of the *leading* (market-mode) eigenvector | Reinstated by explicit request, ahead of `pr_corr_v2` in column order — **not** a re-validated finding: the original audit found this feature substantially redundant with `mu`/`lambda_1` (r=0.74–0.90), which is exactly what RMT theory predicts, since the market mode's own delocalisation and its eigenvalue magnitude both track how uniformly-dominant that one factor is. Read alongside `mu` with that caveat in mind, and treat any effect size attributed to it in isolation with caution until re-measured on the current grid |
| `pr_corr_v2` | `participation_ratio(V[:, 1])` — see below | Localisation/delocalisation of the *second* eigenvector | Least-redundant feature with everything else (r mostly < 0.3 against every other retained feature) — a genuinely orthogonal PCA direction even though its own crisis-conditional effect size is comparatively weak |

**Removed** (still computed internally as part of the eigendecomposition — `lambdas`/`V` are computed in full regardless — just no longer named, returned, or embedded): `lambda_1`, `lambda_1_share` (redundant with `mu`, r≈1.00), `spectral_gap` (redundant with `lambda_1`/`mu`, r≈0.98), `lambda_5` (redundant with `lambda_4_share` and `n_above_mp`), `bulk_dispersion` (redundant with `mu`/`lambda_1`, r=-0.84 to -0.90), `pr_corr_v3` (near-zero standalone separation and sign-unstable crisis effect across markets). `pr_corr_v1` was also removed by the same audit (see the table row above) but has since been reinstated.

**Known open item, not yet fixed**: `pr_corr_v1`/`pr_corr_v2`, like the old raw `lambda_i` before this audit, are **not N-normalised** — a participation ratio of 100 means something different for SP500 (N=350) than a smaller-N market. Not currently a live bug for the pipeline's own clustering (`fit_spectral_embed` fits a separate `StandardScaler` per `(index_code, epoch_length)` combo, which absorbs the level difference within a combo), but flagged for the same reason the raw eigenvalues were normalised — see "Normalisation" below.

## Market mode: `mu` and `sigma_offdiag`

- **`mu`** — mean off-diagonal correlation (`networks.mu_offdiag`, imported directly rather than recomputed, so it is numerically identical to the same quantity already stored in the arm dict as `mu_values` and used by `fit_regime_order` elsewhere in the pipeline). The market mode in random-matrix-theory language: equity correlation matrices are dominated by one eigenvalue far above the Marchenko–Pastur bulk, corresponding to "the whole market moves together," and `mu` tracks that dominance almost exactly (see the table above).
- **`sigma_offdiag`** — standard deviation of the same off-diagonal entries (`networks.sigma_offdiag`, same upper-triangle extraction as `mu_offdiag`, `.std()` instead of `.mean()`). Complements `mu`: two windows can share the same average correlation level while differing in how *uniformly* that correlation is spread across pairs.

## Beyond-market and noise bulk: how much real structure sits above the noise floor

- **`lambda_2_share`, `lambda_3_share`, `lambda_4_share`** — the next three eigenvalues after the market mode, each divided by `N` (candidate sector/style factors, N-normalised for cross-market comparability — see "Normalisation" below).
- **`n_above_mp`** — count of eigenvalues exceeding the Marchenko–Pastur upper edge `mp_edge = (1 + sqrt(N/T))**2` (equivalently `(1 + sqrt(1/q))**2` with `q = T/N`; this is the same formula the since-removed `mg` arm used to define its RMT clipping threshold — see "Arms" in `LOGIC.md` §2) — a standard RMT estimate of how many eigenvalues carry genuine signal rather than sampling noise. Computed over the *full* `lambdas` array rather than the rank-deficiency-filtered `lambdas_nonzero`; verified empirically that this makes no difference (structural zeros can never exceed `mp_edge >= 1`), so it is a harmless implementation detail, not a bug.
- **`spectral_entropy_bulk`** — see "Singularity" below; restricted to the non-structural-zero bulk.

## Eigenvector geometry: `pr_corr_v1` and `pr_corr_v2`

`participation_ratio(v)` computes $\text{PR} = 1/\sum_i v_i^4$ on a unit-L2-normalised vector — the same formula `eigencentrality.py`'s adjacency-matrix PR uses, on a different object: here `v` is one of `C`'s own eigenvectors, not a graph's leading eigenvector. Prefixed `pr_corr_` deliberately, so it is never confused with `eigencentrality.md`'s adjacency-based `pr` in a shared results table. `pr_corr_v1` is `participation_ratio(V[:, 0])` (the market-mode eigenvector's own delocalisation) and `pr_corr_v2` is `participation_ratio(V[:, 1])` (the second-factor loading's) — `participation_ratio` itself is called twice, once per eigenvector, with no other change to the function.

`pr_corr_v1` and the third eigenvector's PR (`pr_corr_v3`) were both computed and reported historically, then removed in the feature-reduction audit; `pr_corr_v1` has since been reinstated (see the table above), `pr_corr_v3` has not. The two removals had different reasons, worth keeping distinct: `pr_corr_v1` was cut for redundancy (it duplicates information `mu`/`lambda_1` already carry), while `pr_corr_v3` was cut for weakness (near-zero standalone separation, sign-unstable crisis effect) — reinstating a redundant-but-real feature is a materially different decision from reinstating a weak one, which is why only the former was acted on here.

## Singularity: `T < N` makes most of the spectrum structurally zero

A sample correlation matrix built from `T` return observations over `N` names has rank at most `min(N, T-1)`, not `min(N, T)` — Pearson correlation demeans each column, which costs one degree of freedom versus the naive `T` count. This is not a rounding nuance: verified directly by eigendecomposing every rank-deficient window in the dataset and comparing the eigenvalue at position `T-2` (the last one the `T-1` cutoff keeps) against the one at position `T-1` (the first one it drops) — the ratio between them never fell below `~7×10^11` (typically real eigenvalues of order `1e-2`–`1`, "extra" ones of order `1e-15`–`1e-14`), i.e. an unambiguous floating-point-noise cliff, not a borderline case.

The S&P panel has `N=350` names, so a `T=132`-day window has `min(350, 131) = 131` non-zero eigenvalues and `350 - 131 = 219` structural zeros; `T=63` gives `288` structural zeros; `T=378 > 350` is well-conditioned with none. The smaller markets have different zero counts at the same `T`s, but the same formula. `window_spectral` computes this by position, not by a magnitude tolerance: `lambdas` is sorted descending, so the trailing `N - min(N, T-1)` entries are exactly the structural zeros (or floating-point noise around zero), and slicing `lambdas[:min(N, T-1)]` before computing bulk statistics avoids ever measuring them as if they were real small-but-nonzero eigenvalues. Every correlation matrix eigendecomposed this way is symmetric to machine precision (`max|C - Cᵀ| = 0`) with its most negative eigenvalue at `~0` (never meaningfully negative), i.e. genuinely PSD as `eigh` requires — this isn't assumed, it's checked.

- **`spectral_entropy_bulk`** is computed only over that non-zero slice, further restricted to eigenvalues strictly below `mp_edge` (the actual RMT noise band, excluding the market mode and any above-threshold factors). Entropy is normalised by `log(count)` (`-sum(p log p) / log(bulk.size)`, with `p = bulk / bulk.sum()`), so it is comparable across epoch lengths even though the bulk's size changes with `T`. The `p log p` term uses `np.log(p, where=p > 0, out=log_p)` rather than a bare `p * np.log(p)` — the same `0·log(0) := 0` convention `eigencentrality.window_centrality`'s entropy uses. Undefined (`NaN`) only if the bulk has ≤1 eigenvalue — not observed in any real window checked, but a latent edge case worth knowing about.
- **`n_zero_eigenvalues`** and **`q = T/N`** are recorded per combo and printed *before* any clustering runs — the same discipline `eigencentrality_sweep_raw.py` applies to `mean_pr`/`median_pr`: report the diagnostic that determines whether the descriptor is even well-defined before anything downstream can be misread as a clean result. Both are **exactly constant** within a given `(index_code, epoch_length)` combo, since both are pure functions of the fixed `(N, T)` — they therefore carry zero within-run discriminating power, which is exactly why they aren't embedded (below).
- These two, plus `mp_edge` (also constant per combo, same reason), are reported diagnostics only — `spectral.SPECTRAL_FEATURE_COLUMNS` excludes them, exactly as `eigencentrality.py`'s `lcc_frac`/`argmax_id` are reported but never stacked into the matrix `fit_centrality_embed` receives.

**A more conservative alternative exists and was not taken**: restricting this whole baseline to `T=378`, the epoch length where the S&P panel is genuinely well-conditioned (`T > N`, zero structural zeros), would be statistically cleaner and is a one-line change (drop `63`/`132` from `EPOCH_LENGTHS`) if the singularity handling above turns out to be a weaker link than it looks.

## Exact reproducibility — no gensim caveat

Unlike Graph2Vec (`graph2vec.md`'s multi-threaded Doc2Vec training is only *approximately* reproducible run-to-run even with a fixed seed), `np.linalg.eigh` on a fixed input matrix is exactly reproducible: same `C` in, same `lambdas`/`V` out, every time, on any machine. This property already holds for eigenvector centrality's `eigsh` call too — this branch doesn't introduce it, but it is worth restating here because this descriptor has no learned component whatsoever (no vocabulary, no training epochs, not even the graph-construction choices — threshold, MST backbone, TMFG triangulation — that the other two branches still make). `StandardScaler`/`PCA` are fit with `random_state=42`, matching the rest of the pipeline, but PCA on already-deterministic input has no seed-sensitivity to begin with.

## Embedding: `fit_spectral_embed`/`transform_spectral_embed`

Mirrors `eigencentrality.fit_centrality_embed`/`transform_centrality_embed` exactly: `StandardScaler` fit on train only, `PCA(n_components=0.95, random_state=42)` fit on the scaled train features, and `transform_spectral_embed` is a plain deterministic projection (`scaler.transform` then `pca.transform`) with no fitting step — never `fit_transform` on the combined train+test set. The 9-column `SPECTRAL_FEATURE_COLUMNS` matrix is what gets scaled and reduced — a market-level fingerprint of a handful of scalars per window, not a per-stock vector (eigenvector centrality's `v1`) or a learned 128-dimensional graph embedding (Graph2Vec). PCA(0.95) previously retained 5–6 of the 8 dimensions in every real combo checked (before `pr_corr_v1` was reinstated); that figure has not been re-measured against the current 9-feature set and should not be assumed unchanged — `pr_corr_v1`'s documented redundancy with `mu` (see "Eigenvector geometry" above) means it may add little to the retained dimensionality, but that is a prediction, not yet a measurement. `modelling.py` is unchanged downstream: `split_train_test`, `k=3`, `cluster_kmeans`/`cluster_hmm` fit on train and predicted on both, `fit_regime_order` on train `mu` frozen via `apply_regime_order`, `validate_regime` against VIX for SP500 only.

## Normalisation: why `lambda_2..4` are `_share`, not raw

Raw eigenvalue magnitude conflates "how many stocks" with "how correlated they are." Confirmed empirically at `T=132`: SP500 (N=350) vs. a smaller-N market's raw `lambda_1` differs by more than the N ratio alone would predict. `lambda_1_share = lambda_1/N` (the pre-audit feature that motivated this convention) collapsed that gap substantially; `lambda_2_share`/`lambda_3_share`/`lambda_4_share` apply the same `/N` convention for consistency. This is not currently a live bug for the pipeline's own clustering — `fit_spectral_embed` fits a separate `StandardScaler` per `(index_code, epoch_length)` combo, so cross-market comparability is never actually exercised — but it matters for reading raw numbers side-by-side across markets and for any future pooled/cross-market embedding. `pr_corr_v1`/`pr_corr_v2` have no such normalisation yet (see the feature table above).

## Raw arm only

`spectral_sweep_raw.py` runs `ARMS = ["raw"]` and all four markets (`INDEX_CODES = ["SP500", "Nikkei225", "FTSE350", "CSI300"]`), with no `graph_type` axis at all (there is no graph), so its grid is `index_code x epoch_length` = 4x3 = 12 combos. The pipeline previously also carried two other correlation transforms (`mg`/`gr`); both were dropped from `networks.py` since the analysis only ever depended on `raw`, so there is no other arm to extend this sweep to.
